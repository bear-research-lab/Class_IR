# Part 3: 피펫팅 핸드

*[English](PART3_HAND.md)*

RB5용 핸드를 설계하세요. 핸드는 홀더에서 피펫을 집어 물통에서 물을 흡입하고, 분주 용기에
분주한 뒤, 피펫을 다시 홀더에 꽂아야 합니다. 로봇은 **공칭(nominal)** 위치만 알고 있습니다.
따라서 홀더의 위치 오차(x, y ±5 mm, 기울기 ±2°)와 피펫 굵기의 차이는 핸드가 흡수해야 하고,
벌브는 **일정한 힘**으로 눌러야 합니다.

바꿀 수 있는 것은 핸드뿐입니다. 로봇 프로그램, 작업 순서, 채점 방식은 고정되어 있고 모두에게
같습니다. 로봇은 Part 1, 2에서 작성한 **여러분의 기구학**(`student_kinematics.py`)으로 움직이므로
그 두 파트를 먼저 끝내세요. 끝나기 전에는 스크립트가 실행을 멈추고 그 사실을 알려 줍니다.

## 1. 준비

```
uv sync                                   # 의존성 설치 (처음 한 번)
uv run pipetting.py                       # 기본 핸드가 작업을 시도하는 모습 보기
uv run pipetting.py --no-error            # ... 홀더가 로봇이 예상한 위치에 정확히 있을 때
```

기본 핸드(`hands/basic/hand.xml`)를 복사해서 그 복사본으로 작업하세요.

```
hands/<팀이름>/hand.xml                    # hands/basic/hand.xml의 복사본
hands/<팀이름>/meshes/...                  # 선택: CAD 메시 (STL/OBJ)
```

## 2. 로봇이 하는 일 (고정)

로봇은 매 실험마다 같은 프로그램을 실행합니다. 공칭 위치만 사용하고, 피펫이 실제로 어디
있는지는 절대 보지 않습니다.

| 단계 | 로봇 동작 | 핸드에 주어지는 시간 |
|---|---|---|
| 1 | 홀더에 수평으로 접근, 그리퍼 닫기, 150 mm 들어 올리기 | 그리퍼 닫기: 0.8초 |
| 2 | 물통 위로 이동, **누르기**, 팁을 수면 아래 25 mm까지 담그기, **놓기** | 누르기/놓기: 각 0.6초 |
| 3 | 분주 용기 위로 이동해 팁을 용기 안으로 내리기 | - |
| 4 | **누르기**, 0.5초 유지, **놓기**, 들어 올리기 | 누르기/놓기: 각 0.6초 |
| 5 | **공칭** 홀더 위치 위로 이동, 피펫을 소켓에 수직으로 내려 꽂기(마지막 15 mm는 천천히), **그리퍼 열기**, 수평으로 빠져나오기 | 그리퍼 열기: 0.6초 |

로봇은 핸드의 `grasp` 사이트를 피펫의 잡는 점이 **있어야 할** 위치로 옮깁니다. 잡는 점은
공칭 피펫 축 위, 팁에서 110 mm 위입니다.

## 3. 피펫

피펫은 홀더에 수직으로 꽂혀 있고, 피펫 좌표계의 원점은 팁에 있습니다.

| 부분 | 축 방향 위치 (팁 기준) | 크기 |
|---|---|---|
| 샤프트 | 0 - 160 mm | **지름 6 - 10 mm** (실험마다 무작위) |
| 잡는 점 (로봇이 손가락이 있으리라 예상하는 곳) | 110 mm | - |
| 벌브 중심 | 180 mm (**잡는 점에서 70 mm 위**) | **지름 16 - 22 mm** (실험마다 무작위), 길이 약 26 mm |

홀더 소켓은 정사각형이고, 샤프트와의 틈새가 1 mm, 깊이가 40 mm이며, 위쪽에 1 mm × 45°의
작은 모따기만 있습니다. 홀더 자체는 최대 ±5 mm(x, y)와 2° 기울기의 오차를 갖고 놓입니다.
피펫을 반납할 때도 홀더는 같은 (어긋난) 위치에 있으므로, 반납은 핸드가 해내야 하는
펙-인-홀(peg-in-hole) 삽입 문제입니다. 유리 샤프트와 홀더 사이의 마찰계수는 0.3입니다.

시뮬레이션에서 피펫은 자기 축을 중심으로 회전할 수 없습니다(실제 벌브는 둥글어서 이 회전은
의미가 없습니다). 벌브의 네 벽은 피펫 좌표계에 맞춰 정렬된 채로 유지되므로, 벌브는 핸드의
y축이나 z축 방향으로 누르세요. 대각선으로 누르면 안 됩니다.

벌브는 유연합니다. **600 N/m** 스프링에 달린 고무벽 네 개로 되어 있고, **6 mm** 압축되면 완전히
납작해집니다. 한쪽당 누르는 힘은 600 N/m × 압축량입니다.

## 4. 핸드가 갖춰야 할 인터페이스

`hand.xml`은 RB5 플랜지에 부착됩니다. 다음을 반드시 포함해야 합니다.

1. `<worldbody>` 안에 **루트 바디가 정확히 하나**(핸드) 있어야 하고, 그 좌표계가 플랜지입니다.
   - **z**: 플랜지 밖으로 향하는 방향(접근 방향. 핸드는 +z 방향으로 피펫에 다가갑니다)
   - **x**: 피펫 축 방향, 팁에서 벌브 쪽(작업 중에는 위쪽)
   - **y**: 오른손 좌표계를 완성하는 방향(작업 중에는 수평)
2. 핸드에 단단히 고정된 바디(움직이는 손가락이 아닌 곳)에 **`grasp`라는 이름의 사이트**.
   로봇은 이 사이트를 공칭 잡는 점에 놓고, 사이트의 축을 위의 핸드 축에 맞춥니다.
   기본 핸드에서는 `pos="0 0 0.09"`, 즉 플랜지 앞 90 mm에 있습니다.
3. 샤프트를 잡는 **`gripper`라는 액추에이터**와 벌브를 누르는 **`squeezer`라는 액추에이터**.
   액추에이터 종류는 자유입니다(`position`, `motor`, `general`, ...).
4. 로봇이 각 명령에서 보내는 `ctrl` 값을 정하는 **numeric 네 개**. 값의 의미는 액추에이터에
   따라 다릅니다. position 액추에이터라면 이동 거리(m), motor라면 힘(N) 등입니다.

```xml
<custom>
  <numeric name="gripper_open"    data="0"/>
  <numeric name="gripper_close"   data="0.03"/>
  <numeric name="squeeze_release" data="0"/>
  <numeric name="squeeze_press"   data="0.0275"/>
</custom>
```

빠진 것이 있으면 스크립트가 멈추고 무엇이 빠졌는지 알려 줍니다.

## 5. 규칙

- `hands/<팀이름>/` 안의 파일만 수정하세요. `rb5_sim/`, 스크립트, `assets/`는 바꾸지 마세요.
- **액추에이터는 두 개뿐**: `gripper`와 `squeezer`. 나머지는 모두 수동 요소여야 합니다.
  스프링(`stiffness`), 댐퍼, 관절 한계, equality 구속, 텐던, 접촉 등입니다.
- **힘 제한**: `gripper`는 최대 **20 N**, `squeezer`는 최대 **15 N** (`forcerange`로 설정).
  관절에 걸리는 힘 기준입니다. `gear`나 텐던 `coef`를 쓰면 그만큼 곱해집니다.
- **핸드 질량**은 전체 **1 kg** 이하.
- **핸드만**: `hand.xml`은 자기 부품만 참조할 수 있습니다 (피펫이나 주변 물체와의 weld,
  contact pair, exclude 금지).
- **제작 가능성**: 모든 수동 관절, 스프링, 구속은 실제 메커니즘(예: 리니어 가이드와 압축
  스프링, 플렉셔)에 대응해야 하고, 3D CAD 설계에 그 메커니즘이 보여야 합니다. 발표에서 각각을
  설명하세요.

스크립트가 액추에이터, 힘 제한, 질량, "핸드만" 규칙을 검사하고, 어기면 메시지를 띄우고
멈춥니다. 점수는 기본값 `--motion-scale 1`일 때만 인정됩니다.

## 6. 채점 방식

```
uv run evaluate_hand.py --hand hands/<팀이름>/hand.xml --seed 0
```

실험 5회를 실행합니다. 실험마다 무작위 피펫(샤프트와 벌브 지름), 무작위 홀더 오차, 그리고
`layouts.md`의 배치 하나를 사용합니다. 각 실험은 0에서 1 사이의 보상을 받습니다.

```
reward = gate × exp(-(RMS 힘 오차 / 0.5 N)²)
```

- **gate**는 모든 작업 검사를 통과했을 때만 1이고, 아니면 보상은 0입니다. 검사 항목은 다음과
  같습니다.
  - 피펫을 집어 올렸는가
  - 벌브를 놓을 때 팁이 물속에 있는가
  - 팁이 분주 용기 안에 있는가
  - 벌브를 놓았는가
  - 충돌이 없었는가 (집어 올린 후부터 반납 전까지 주변 물체가 피펫에 가한 힘이 10 N 이하)
  - 피펫을 **반납**했는가 (소켓 바닥에서 5 mm 이내로 안착, 삽입력 최대 **15 N**)
- **RMS 힘 오차**는 벌브를 누르고 있는 동안(물에 담글 때와 분주 유지 시간)의 모든 순간에 대해
  **한쪽당 2.5 N** 목표와 비교해 계산합니다. 힘의 크기가 틀려도, 힘이 흔들려도 점수가 깎입니다.

| 목표와의 차이 | 0 N | 0.25 N | 0.5 N | 1 N |
|---|---|---|---|---|
| 보상 | 1.00 | 0.78 | 0.37 | 0.02 |

**점수는 보상의 평균입니다.** 시드 0-4(각각 `-n 5`, 실험 25회)를 기본 설정으로 실행한 결과이며,
발표에서 보여 줍니다(8절). 시드 하나가 아니라 피펫과 홀더 오차의 전체 범위에 맞춰 설계하세요.

기본 핸드는 평평한 손가락의 단순한 평행 그리퍼에, 항상 같은 위치까지 미는 벌브 누르개를 단
핸드입니다. 홀더가 로봇이 예상한 위치에 정확히 있으면(`--no-error`) 모든 검사를 통과하지만,
`--seed 0`에서는 **0점**입니다. 홀더 오차가 있으면 피펫을 반납할 때 끼이고, 가끔 피펫을
떨어뜨리거나 넘어뜨리며, 굵은 벌브와 가는 벌브를 전혀 다른 힘으로 누릅니다. 직접 실행해서
어디서 실패하는지 보고, 거기서부터 시작하세요.

## 7. 유용한 명령

```
# 슬로 모션으로 핸드 보기 (벌브 힘과 팁 높이 그래프 포함)
uv run pipetting.py --hand hands/<팀이름>/hand.xml --playback 0.5

# 무작위 피펫 10개로 채점, 첫 번째는 뷰어로 보기
uv run evaluate_hand.py --hand hands/<팀이름>/hand.xml --seed 0 -n 10 --visualize 1

# 견고성 확인: 다른 시드, 벌브 힘 그래프 저장
uv run evaluate_hand.py --hand hands/<팀이름>/hand.xml --seed 1 -n 10 --plot forces.png

# 뷰어 없이 한 번 실행, 전체 힘 그래프와 CSV 기록 저장
uv run pipetting.py --hand hands/<팀이름>/hand.xml --headless --plot run.png --csv run.csv
```

검사에 실패하면 어떤 검사가 왜 실패했는지 출력됩니다(예: 팁 위치 오차 mm). 힘 요약에는 작업
단계별로 그립 힘, 벌브 힘, 주변 물체와의 힘이 나옵니다.

## 8. 최종 발표

제출할 파일은 없습니다. 팀별로 발표하며, Part 3에서는 다음을 보여 주세요. 기본 핸드가 홀더 오차
없이 작업하는 모습은 [참고 영상](https://youtu.be/VN9uyTWR938?t=38)에 있습니다.

- 홀더 오차가 있는 상태에서 여러분의 핸드가 작업하는 **영상**. 기본 핸드가 실패하는 시드를
  하나 이상 포함하세요. 녹화 명령:
  `uv run pipetting.py --hand hands/<팀이름>/hand.xml --seed 3 --headless --video part3.mp4`
- 설계: 홀더 오차를 어떻게 흡수하는지(잡을 때와 반납할 때), 샤프트 지름 차이를 어떻게
  처리하는지, 누르는 힘을 어떻게 일정하게 유지하는지.
- 시뮬레이션의 각 관절, 스프링, 구속에 대응하는 실제 메커니즘.
- 핸드의 **3D CAD 설계**(다음 강의에서 다룹니다): 부품 구성, 각 수동 관절과 스프링이 CAD에서
  어떤 부품으로 구현되는지, `hand.xml`의 치수가 CAD와 어떻게 대응하는지.
- 결과: 시드 0-4에 대한 `evaluate_hand.py` 결과표(각각 `-n 5`), 평균 점수, 힘 그래프
  하나(`--plot`).
- 여전히 실패하거나 점수가 낮은 부분과 그 이유.
